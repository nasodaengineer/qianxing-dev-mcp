# qianxing-minigame-design

## Suggested name
小玩法从构思到试玩清单

## Suggested description
在创作者要从一个玩法点子落地成可试玩关卡、需要端到端步骤清单（场景→触发→变量→UI→结算→试玩）时使用。可与其它分册技能联用。

---

## Body

### 目标
把「想法」收敛成 **最小可玩切片（vertical slice）**：1 个目标 + 1 种核心操作 + 1 次胜负/得分反馈，再迭代。

### 0. 先问清（必问）
- 人数：单人 / 多人？对抗还是合作？
- 模式：经典 / 超限？（影响职业节点图、角色技能图等）
- 核心循环一句话（例：30 秒内踩点得分）
- 是否需要自定义技能/职业，还是只用机关 + 默认角色

### 1. 关卡骨架
1. 新建/打开存档；系统菜单确认可保存。
2. **关卡设置**：人数、出生/预设点、阵营（若对抗）、负载档位、加载界面。
3. 地形或 **场景生成模板** 快速铺底，玩法关键区用 **动态实体** 手摆。

### 2. 核心交互（通常优先碰撞触发）
- 区域类：触发器（场地）+ 触发源（玩家默认有）+ 实体节点图监听进入/离开。
- 攻击类：命中检测 / 受击盒 + 阵营关系。
- 需要多方响应：用 **信号** 解耦，避免一个图操作所有实体。

### 3. 数据
- 得分、剩余时间、开关状态 → 优先放在 **关卡实体或玩家实体的自定义变量**。
- 仅某张图内部的临时数据 → **节点图变量**。
- 需要给 UI/本地过滤器读的变量 → 必须在自定义变量组件里 **预定义**（才会同步本地）。

### 4. 反馈
- 特效播放组件 / 节点「播放特效」
- 简单 UI：界面控件组 + 布局；计分板/计时器等预制控件
- 文本气泡、铭牌（可选）

### 5. 战斗向扩展（按需）
- 只要机关玩法可跳过。
- 需要职责分化 → 职业打包技能与属性。
- 自定义出手 → 战斗预设新建技能，时间轴挂客户端节点图，必要时信号回服务端改分。

### 6. 结束条件
- 节点图调用 **关卡结算**；先正确设置各玩家结算状态（胜利/失败/未定）与逃跑合法性。
- 试玩阶段可关「启用试玩结算」加速迭代。

### 7. 验证闭环
1. 系统菜单 **风险检查**（非阻断，但能扫隐藏配置问题）。
2. **试玩**：选玩家编号；失败看错误码。
3. 沙箱 **日志**：筛选相关节点图，核对事件是否触发、参数是否预期。
4. 看 **负载检测 / 关卡负载**；布景过密则静态化或减生成密度。
5. 稳定后：`.gia` 导出可复用元件+节点图组合包。

### 推荐最小实例：「踩圈得分」
1. 地面放触发器物件（动态）+ 大触发区，生效目标勾选角色。
2. 关卡实体自定义变量 `Score`（整数）。
3. 触发器实体节点图：`进入碰撞触发器时` → 取进入者 → 取归属玩家 → `Score += 1`（并可选是否触发变量变化事件）。
4. UI 计分板绑定/读取该变量（或变量变化时刷新）。
5. 定时器到时 → 设结算状态 → 结算关卡。
6. 试玩验证。

### 协助时应索取
- 玩法一句话 + 胜负条件
- 当前关卡设置（人数/阵营）截图
- 核心机关的组件与节点图截图
- 试玩结果：成功路径 / 失败现象 / 错误码
